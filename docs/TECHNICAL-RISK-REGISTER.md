# Version 0.8 technical risk register

Review date: 10 August 2026

## Status and claim boundary

This register separates software correctness from accessibility evidence. Automated
tests can establish deterministic state, scoring, validation and recovery behaviour in
the tested implementation. They cannot establish browser speech-recognition accuracy,
WebGazer accuracy, assistive-technology usability, psychometric equivalence or benefit
for people with impairments.

The current build is a release candidate. Real recruitment uses the re-tested
prototype only after the actual UCL Qualtrics survey exports a complete synthetic
response and the final procedure is confirmed as covered by the project's
existing approved protocol and data-management route.

## Current risks and controls

| ID | Risk and consequence | Current control | Evidence now | Remaining gate |
| --- | --- | --- | --- | --- |
| R1 | The three required Qualtrics inputs are pasted into the wrong locations, mixed across versions or left as unpublished draft changes, producing a blank iframe, clipped page, visible tokens or empty fields | The conductor separates three required code/data blocks from one optional plain-text final message; the parent and child require the exact `0.8.7-q7` build; guidance requires Review and Publish | Component, template, mismatch and handshake tests | Install in the UCL tenant from a blank survey, publish and repeat the guide cold |
| R2 | A parent acknowledgement is mistaken for a server-recorded Qualtrics response | The interface describes the acknowledgement as browser-page staging that is not yet recorded. A failed-advance message updates visible and spoken participant feedback; only a submitted Qualtrics row is recorded evidence | State, bridge and failed-advance message tests | Observe and export one synthetic Data & Analysis row |
| R3 | The tab is closed after acknowledgement but before Qualtrics navigation completes | A complete local backup is attempted before host contact and remains discoverable on the same device | Component close/reopen test | Close immediately in the UCL survey and check the remote row separately |
| R4 | Network or parent failure loses answers or creates false completion | Failure returns to Review with focused error, retry, edit and JSON/CSV routes | Rejected-host and timeout tests | Interrupt the real network during a UCL preview run |
| R5 | Browser storage is blocked or full | Submission remains available in memory; no false local-save claim; downloads stay visible | Storage unit and component tests | Repeat in browser privacy/storage-restricted modes |
| R6 | Spoken landmark language changes a rating's meaning | Visible labels map to 0, 25, 50, 75 and 100; ranked hypotheses use the first safe visible-answer match; exact bounded aliases and standalone number homophones improve common transcriptions; unresolved negation/exclusion in any alternative rejects the entire result; arbitrary prose is never mined for a number; confirmation is mandatory | Parser and component regression tests, including both `4`/`Note 4` rank orders | Microphone test in each supported browser and accent context |
| R7 | The browser speech service is unavailable, transcribes inaccurately or removes a spoken negation entirely | Voice is optional; supported browsers receive contextual hints for current visible answers; rejected as well as accepted transcripts are displayed; visible native controls and system voice control remain available; the chosen transcript and proposed answer are shown and announced before confirmation. Client code cannot recover a word absent from all returned alternatives | Component and contextual-hint tests | Record browser/device support, returned alternatives and observed transcripts; verify that an incorrect proposal is never recorded without confirmation |
| R8 | A missing Qualtrics iframe hides native navigation and traps the page | The bridge reports the missing iframe and leaves native navigation available; this must fail preflight | Executed bridge test | Confirm the UCL theme does not suppress the status or navigation |
| R9 | Literal Qualtrics piped-text tokens in the editing canvas are mistaken for participant output | Setup guidance distinguishes the editor from Preview and explains the conditional recorded-response summary | Documentation and generated-package checks | Confirm the live preview shows the iframe and a recorded response shows the summary |
| R10 | WebGazer is treated as accurate independent eye control | Gaze is labelled experimental, starts off by default and requires a separate confirmation | Mocked state tests and manual functional checks | Keep the result Partial unless target accuracy is measured with an approved protocol |
| R11 | Keyboard, screen reader, reflow, selection or focus behaves differently inside the Qualtrics iframe | Native controls, focus movement, status regions and exact iframe title are implemented; the iframe is the only visible full-viewport scroller; selected states persist with a check/label; control, selected, focus and gaze indicators use calculated ≥3:1 authored contrast | Axe structural scans, interaction tests, full-viewport bridge test and calculated contrast audit | NVDA/VoiceOver, forced colours, 200% zoom, 320 CSS-pixel reflow and mobile UCL-preview tests |
| R12 | Optional wording, smileys or input routes are described as psychometrically equivalent or more accessible without evidence | Definition capability gates preserve official items/scoring; support use is logged separately; SUS disables unsupported wording/smileys; claims are explicitly bounded | Definition/content/scoring tests and public documentation | Approved evaluation with appropriate outcomes and participants |
| R13 | Automatic built-in speech omits feedback, falsely implies durable recording or is cut off when Qualtrics replaces the iframe | New questions, Smiley values, selections, proposals, simpler help, recovery, errors and local completion are spoken. Parent staging is explicitly described as not yet recorded, and a failed native advance sends corrective visible and spoken feedback to the iframe | Component audio, bridge-message tests and handoff documentation | Manual speech-synthesis test in each browser and the actual UCL Qualtrics iframe |
| R14 | Built-in speech sounds different or poor on a particular device | The application requests English at neutral rate/pitch/volume and no longer forces the first returned voice; external screen readers and visible text remain independent routes | Unit check that no enumerated voice is forced | Record the actual system voice, quality and volume on every supported device |
| R15 | Re-entering a participant code after a reload increases memory and task burden, while a stale or malformed link can associate answers with the wrong pseudonymous identity | A participant-specific link prefills an editable code. A different valid link overrides stale tab data; after Start and a successful progress save, an explicit manual correction is bound to that same link for reload recovery. A malformed non-empty link code is shown as invalid and cannot restore a stale identity; a missing code remains a manual fallback. The active code and link binding are held only in tab-scoped session storage, while progress remains keyed by the same validated code | Component tests cover link prefill/editability, new-link precedence, corrected-code reload through final result export, missing-code fallback, malformed-code rejection and saved-progress focus/announcement | Re-test browser session restore, iOS speech policy, shared-device procedure and participant wording; retain manual correction as a fallback rather than claiming identifier errors are eliminated |
| R16 | Questionnaire-independent is misreported as support for any questionnaire | Public scope lists the built-in instruments and bounded researcher-supplied integer single-choice profile; unsupported fields/types fail closed | Architecture document, JSON Schema and semantic rejection tests | Keep the dissertation and participant materials within the same claim boundary |
| R17 | A definition selects a scorer that does not match its items or scale | JSON cannot contain executable code; scorer names are allowlisted; weighted NASA-TLX, Raw TLX and SUS have distributable instrument-specific semantic compatibility checks; the retained centred-score extension is exercised only with original synthetic content | Definition and scorer regression tests | Review every future scorer, item source and redistribution permission before registration |
| R18 | The participant runner supports several instruments but Qualtrics silently stores only NASA fields | Version 0.8 uses generic `AQP_*` identity, answer, score, support and raw-record fields | Executed bridge tests with non-NASA data | Observe/export at least weighted NASA-TLX and one non-NASA row in the UCL tenant |
| R19 | A Version 0.7 Qualtrics survey is reused with a Version 0.8 participant link, or blank new columns are mistaken for deleted old data | Migration guide requires replacement of all four integration inputs; Version 4/`AQP_*` records fail closed against old setup; the conductor explains that old rows remain under `ANTLX_*` and are not backfilled | Migration documentation, conductor warning and schema checks | Create a new/copy UCL survey, export and verify old fields, and archive the exact configuration |
| R20 | Qualtrics theme wrappers clip a measured-height iframe or create two scrolling regions | The live wrapper is moved to the document body, fixed to the visual viewport, outer scrolling is disabled and the participant document owns one scrollbar; no child-height measurement is used | Full-viewport parent-bridge and generated-template tests | Confirm one-scroll reflow in UCL Preview on desktop, phone and tablet |
| R21 | A rendered iframe or an older Data & Analysis row is mistaken for proof that `AQP_*` fields will be recorded | The bridge is hidden until the exact-origin, exact-build child handshake succeeds, stages build diagnostics and the conductor requires publishing plus a newly dated synthetic row; old rows are explicitly excluded | Bridge, generated-package and migration tests | Confirm a new post-publication UCL row has `AQP_ACCEPTED=1`, schema 4 and the expected instrument ID |
| R22 | Intermediate response positions are given invented labels, or voice recognition treats a partial endpoint word as a displayed response, changing response semantics | The runner preserves declared labels, leaves undeclared intermediate positions unlabelled, accepts a displayed number or complete visible endpoint only, and requires confirmation; ambiguous, conflicting and negated alternatives fail closed | Definition, parser, component and end-to-end regression tests using SUS and original synthetic semantic-differential content | Microphone and screen-reader check of both endpoints and one intermediate value in every released labelled scale |
| R28 | A Version 4 configuration or stored result is altered and its fingerprint is deleted so that a compatibility migration silently blesses the changed definition | Version 4 requires a present, canonical matching fingerprint at configuration load, submission and stored-result restoration; only the separately validated Version 3 legacy path migrates | Stale-hash and missing-hash tampered-link/result tests; submission-time recomputation | Keep Version 4 hashless migration absent; treat any future schema migration as a new reviewed boundary |
| R29 | Third-party questionnaire wording is published under the software licence without permission | MIT scope excludes third-party questionnaire content; UEQ-S item text and catalogue entry are removed until written permission covers repository and deployment | Release-directory inventory test, exact-wording repository search and third-party notice | Archive written permissions and regenerate all evidence before restoring any removed instrument |
| R23 | A researcher-supplied questionnaire executes code, silently changes a built-in definition or uses an unsupported scoring formula | Custom input is validated as data only; unknown fields, built-in-ID replacement and scorers outside the mean/sum allowlist are rejected | Custom-definition rejection and resolver tests | Repeat one cold import with a valid definition and one deliberately invalid file |
| R24 | A custom participant URL or raw Qualtrics record becomes too large and fails during installation or collection | Custom definitions are limited to 20 items and 9,000 UTF-8 bytes; generated participant URLs are capped at 24,000 characters; Qualtrics independently rejects records outside its 24×900-character raw allocation while the local backup remains available | Definition-size, URL and bridge-allocation checks | Generate the longest planned real definition and complete one synthetic UCL Qualtrics response |
| R25 | Technical validation is mistaken for permission, psychometric validity or suitability of a researcher-supplied questionnaire | The builder displays a permission/validity boundary; the result preserves source/authorship, version and the complete definition snapshot | Builder content, definition round-trip and result-export tests | Protocol review must cite the source, scoring rationale, population and permission before recruitment |
| R26 | An “anonymous” Qualtrics link is assumed to make the dataset anonymous, while Qualtrics still records IP address and approximate location by default | Conductor and integration guidance require an explicit Survey Options decision, publication and inspection of a newly exported row; the participant code remains pseudonymous and is not treated as proof that all metadata is anonymous | Official Qualtrics behaviour documented; synthetic export inspection detects populated IP and location fields | Enable **Anonymize responses** unless the approved protocol requires those fields, then verify that new exported rows match the decision |
| R27 | A structured export contains unsupported questions or logic and the importer silently creates a different questionnaire | Import review separates accepted, confirmation-required and unsupported content. Multi-group LSS requires an explicit group choice; mixed groups require a compatible rating-set choice; LSQ warns that survey/group context is absent; every omitted source question is named. Unsafe behaviour inside the selected set blocks conversion | QSF/LSS/LSG/LSQ type, logic, group-selection, rating-set-selection, mixed-scale and no-silent-omission tests | Repeat with real supported and deliberately unsupported exports from both platforms |
| R28 | Source answer order or numeric recodes change during conversion and produce a plausible but incorrect score | QSF `ChoiceOrder`/`AnswerOrder` and explicit recodes, or LSS answer sort order and explicit numeric codes/assessment values, are required and preserved; the researcher confirms the review | Real-format fixture order, label, score, JSON round-trip and end-to-end export tests | Compare converted JSON against source-platform screens and scoring instructions |
| R29 | Imported markup, formulas or scripts execute in the participant page | Import uses safe visible-text extraction; script elements, event handlers, JavaScript URLs, dynamic expressions and arbitrary formulas block conversion; the result then passes strict definition validation | Executable/dynamic-content and unknown-field rejection tests | Retain hostile fixture regression tests for every importer change |
| R30 | A file is structurally convertible but its scoring, permission or measurement validity is inferred incorrectly | Recodes are not treated as a scoring formula; mean/sum and reverse-scored items require explicit confirmation; source and complete definition are preserved | Confirmation-gate, scorer allowlist, definition snapshot and result-export tests | Verify authoritative scoring and permission outside the software before study use |
| R31 | A release changes the saved-progress/result schema, or an imported definition changes while a participant has an unfinished copy | Every new session stores its versioned definition snapshot and recovery requires an exact match. Valid Version 3 weighted NASA-TLX progress and completed backups have separate, strictly validated migrations; completed scores are recalculated before Version 4 is written. Invalid current copies show a restart path, while incompatible legacy copies remain untouched rather than guessed or deleted | Valid, invalid and changed-definition progress tests; valid/tampered completed-backup migration tests; migration documentation | Before recruitment, exercise interrupted and completed Version 0.7 synthetic copies in the frozen deployment; any future schema change requires its own explicit migration and regression test |

## Required pre-recruitment decision

Treat an item as resolved only when its remaining gate has an observed result, date,
browser/device, frozen Git commit, Qualtrics survey version and supporting evidence.
Record Pass, Partial, Fail or Not supported. A passing automated test must not be
copied into the dissertation as participant evidence.
