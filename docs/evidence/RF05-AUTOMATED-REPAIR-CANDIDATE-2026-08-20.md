## Historical defect boundary

The frozen q8 evidence identified narrow-view reflow failures rather than missing content or score logic:

- R1: at 320 CSS px, the expanded voice-unavailable panel produced document-level horizontal scrolling.
- R4: response-option / selected pairwise content exceeded the narrow content area and required horizontal scrolling.

The repair is therefore scoped to participant layout and does not alter questionnaire wording, answer values, scoring, storage, collection, recovery or assistive-technology announcement logic.

## Retained implementation

`source/src/rf05-reflow.css`, imported after the existing participant stylesheet, adds a narrow-view reflow guard that:

- removes the participant page's fixed `min-width: 320px` pressure;
- gives the relevant panel, voice, fieldset, choice and anchor containers a zero min-content floor and bounded width;
- permits long labels, anchors and selected-state badges to wrap;
- allows choice/toggle rows to wrap on narrow screens;
- reduces narrow voice/fieldset inline padding and collapses explanation grids to one flexible column;
- deliberately does **not** hide or clip horizontal overflow.

Generated participant release assets were regenerated by CI rather than hand-edited. The temporary write-enabled synchronization workflow was restored to the canonical read-only workflow and is not part of the final PR changed-file set.

## Automated guard

Cross-browser test: `source/tests/e2e-support/rf05-reflow.spec.ts`.

At a 320 × 900 CSS-pixel viewport, with a reserved vertical-scrollbar gutter to reproduce the historical min-width pressure, it measures document `scrollWidth` against `clientWidth` across:

1. introduction;
2. rating item;
3. expanded voice panel;
4. selected rating states;
5. pairwise choices;
6. selected pairwise choice.

It runs in Chromium, Firefox and WebKit and reports overflowing elements if document-level overflow exceeds one CSS pixel. The state setup uses native DOM click only to reach the relevant rendered states; this test is measuring reflow rather than pointer hit-testing.

## Manual post-fix A22 rerun

The frozen A22 procedure requires 320 CSS px and, **separately**, 200% browser zoom in the normal full-screen viewport. The manual rerun was completed on all four named routes.

### R1 — NVDA + Firefox

**Post-fix result: P.**

At 320 CSS px, the previously failing expanded voice-unavailable state no longer produced document-level horizontal scrolling. Response options remained within the available width and long content reflowed. The auditor also observed that gaze-related content remained visible. Two vertical scroll containers were visible in Firefox in one observation; this is retained as a note but does not itself violate A22 because the frozen criterion concerns required two-dimensional/horizontal scrolling for ordinary content.

Therefore historical **R1-A22: F → P** in separate post-fix evidence.
