# AI-Assisted Development Notes

This file records the software-development use of generative AI tools. The formal thesis disclosure must appear in the thesis outside the appendix and must match the final submitted work.

## Uses in this repository

Generative AI tools assisted with:

- drafting and revising TypeScript, JavaScript, CSS, tests, and documentation;
- proposing accessibility and recovery implementations for review;
- comparing implementation approaches and official documentation;
- generating test cases and release-maintenance scripts;
- reviewing repository structure, evidence records, and release provenance;
- editing technical prose for clarity and consistency.

One merged commit credits `Codex` as a co-author. This is part of the repository history. Removing that credit would require rewriting the released history and would break existing commit and evidence identifiers, so the history is retained.

## Author responsibilities

The author remained responsible for:

- defining the research scope, requirements, and claim boundary;
- deciding which proposed implementation to retain or reject;
- running the prototype and reviewing visible behavior;
- conducting and recording the named NVDA, VoiceOver, and Windows Voice Access checks;
- deciding Pass, Fail, and Not applicable outcomes;
- rejecting a passing claim when real assistive-technology evidence did not support it;
- checking questionnaire wording, scoring, source permissions, and references;
- approving pull requests, releases, and the final dissertation text.

## Evidence rule

AI output, source code, and automated tests are not treated as evidence that a real assistive technology worked. Manual claims use the recorded observation from the named device, browser, and assistive-technology route. Unsupported repair attempts remain documented as failures or are excluded from the executable release.

## Thesis statement preparation

The final thesis statement should name the tool classes used, the parts of the work they assisted, and the author's checking process. It should not state that AI was used only for grammar if it also assisted with code, tests, analysis, or documentation. It should not claim independent authorship of AI-drafted code without describing the review and verification performed.
